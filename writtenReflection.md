For this project, I designed the customer support agent as a tool-using AI system rather than relying only on the language model. A key design decision was to use Amazon Bedrock AgentCore Gateway with MCP tools for order tracking and refund processing, while using a Knowledge Base for product and loyalty information. I also used AgentCore Memory to preserve customer preferences across sessions and Code Interpreter for loyalty discount calculations. This separation lets each task use a tool suited to its purpose and keeps the model from having to invent information.

One of the biggest challenges was integrating the different AgentCore components and debugging the deployed runtime. My local tests were working, but the deployed agent initially failed because its execution role did not have permission to call GetMemory on the existing AgentCore Memory resource. I resolved this by importing the existing Memory resource into the AgentCore project so the required IAM resources and policies were deployed. I also had to strengthen the agent instructions after discovering that the model could reinterpret a correct loyalty calculation returned by the tool.

One challenge I encountered was connecting the AgentCore Gateway to the refund-processing Lambda. Initial order-tracking requests worked, but refund operations failed with permission-related errors. I investigated CloudWatch logs and AgentCore invocation output to identify the failing component. The issue was caused by missing permissions on the Gateway execution role. I updated the IAM permissions to allow the Gateway to invoke the refund Lambda, redeployed the configuration, and retested using the MCP Inspector and AgentCore test conversations. After verifying that refund requests returned valid refund IDs and status information, I confirmed that the integration was functioning correctly.

For production, I would focus on security, reliability, observability, and cost control. Gateway and IAM permissions should follow least-privilege principles, especially for refund operations. Production deployments should include monitoring and CloudWatch alarms for runtime errors, along with structured logging and tracing for tool calls. I would also add stronger validation and error handling around external services and ensure sensitive customer information is not unnecessarily stored in memory or logs. Finally, I would monitor Bedrock, Code Interpreter, Gateway, and other AWS resource usage to control operational costs.
